# Spring AI Alibaba Agent Framework 工具权限改造计划

现有框架可以根据工具元数据和 `HumanInTheLoopHook` 请求审批，并通过 Graph 检查点保存调用批次和审批决定。工具筛选解决模型能看到哪些工具，拦截器提供应用扩展点。框架仍缺少可配置的拒绝规则、统一的默认决策，以及内置文件工具的路径权限。在审批与执行之间，拦截器还可以改写调用，因此两处都需要检查。

Deep Agents 的文件权限使用 READ 与 WRITE、顺序规则和允许、拒绝、人工审批三种决策。它对内置文件工具定义了覆盖范围，并将 shell、MCP 和自定义工具的资源访问交给各自的运行边界。Spring AI Alibaba 采用相同的声明式思路，并复用已有的 Graph 审批协议。[Deep Agents Permissions](https://docs.langchain.com/oss/python/deepagents/permissions)

## 实施

1. 在 Agent Framework 增加可选的 `ToolPermissionPolicy`。调用者声明规则顺序和未匹配时的决策。工具名规则覆盖 ReactAgent 分发的回调，自定义谓词可以读取调用参数与可信运行上下文。原有审批元数据与 Hook 仍然有效。
2. 模型调用结束后先按权限规则判断是否送审。审批批次将拒绝项单独记录。在工具节点进入拦截器前与实际派发前检查权限。审批只覆盖已确认的工具和参数，编辑后的调用仍受拒绝规则约束。
3. 为 `FilesystemInterceptor` 提供文件和目录树规则。单文件使用声明顺序，目录扫描保守检查访问范围。规则校验路径与符号链接，批量工具跳过符号链接文件。Shell、MCP 和自定义回调由应用单独授权并约束其内部资源访问。
4. 提供本地脚本模型示例，演示读取、禁止访问及审批后写入。同步更新网站的 Agent Framework 人机协同指南。

## 验收

- 用离线测试覆盖首条命中、默认拒绝、混合审批批次、拒绝规则优先于审批、审核编辑及拦截器改写，以及目录扫描和符号链接的路径边界。
- 回归现有审批、检查点恢复、动态工具和并行工具用例。编译并运行文档示例，构建网站。
- 子 Agent 按各自的 Builder 配置权限。应用可在多个 Agent 之间复用同一份不可变规则。自动推导委派权限需要子调用的工具注册和上下文契约，可作为独立演进项。
